# 日常安装与启动器集成

`ZMLSetup-*.exe` 是独立 x64 GUI 安装器，内嵌加载器产物，无需 Python、CMake、SDK 或下载运行时。使用 Windows 10/11 自带的 .NET Framework 4.x。安装器 PE manifest 为 `requireAdministrator`，进入后仍检查管理员身份；日常桥接入口同样为 `requireAdministrator`，匹配原生启动器权限，正常请求 UAC，不绕过权限。

## 使用

1. 建议先退出鹰角启动器（不必停止游戏）。双击安装器，同意 Windows UAC；若有残留进程，安装器会在安装前询问，不会静默结束。
2. 首屏逐项勾选五条使用须知（非官方关系、用户协议、游戏平衡、社区行为、账号封禁风险）；全部确认才能点击“下一步”。不提供全选，不保存或上传确认记录，每次运行都需重新确认。
3. 安装页只选择包含 `Launcher.exe` 和版本号子目录的鹰角启动器目录。注册表找到有效位置会预填，未找到保持空白；无需填写 `Endfield.exe`。点击“安装 / 修复”。成功后弹出完成提示，确认后自动关闭安装器；失败则显示错误并保留窗口供重试。
4. 正常打开启动器。“开始游戏”胶囊比原生宽度增加一个 52px 模组按钮，四格模组按钮与原“游戏选项”按钮并列在胶囊内；下方新增原生风格的“加载模组”勾选项，默认不勾选并记住个人选择。未勾选走原普通启动；勾选后直接点击原主按钮加载模组，无需进入模组页面。仅终末地已就绪的开始游戏动作接入，下载、更新、登录、其他游戏与游戏选项不拦截；未知页面结构/按钮文本不猜测。DX11 选项仍由原启动器自己的处理函数读取，加载器不重新拼装参数。
   点击模组按钮从右边展开白灰/黑色玻璃侧栏，保持启动器圆角与字体。每行 58px，显示图标、名称、完整版本、标签和单行省略简介；点击条目展开完整简介、作者、ID、标签和依赖。支持全部/启用/禁用筛选、搜索、刷新、独立开关及打开模组文件夹。
5. 模组放在 `<启动器目录>\ZML\mods\<模组目录>\mod.ini`，不是游戏目录。开关会保存，下一次启动游戏生效。启用时自动补齐已安装依赖；禁用时连同依赖它的模组关闭，额外变化先确认。缺失依赖、循环、重复 id、损坏的模组或外部并发修改会报告错误，不静默忽略。
6. 再运行安装器选择“卸载集成”，恢复原入口及网页。模组、私人配置、备份和安装凭据保留，不删除用户数据。

## 实现与安全边界

- 本机 1.6.0 启动器确认为 Qt5 WebEngine + 本地 React 网页：`<版本>\res\web\index.html` 引用 `qrc:///web/js/qwebchannel.js`，组件树根为 `root`。安装器只在受支持的网页追加自己命名的 CSS/JS；不改压缩业务 JS、Qt DLL、账户数据库、日志或游戏文件。
- 根 `Launcher.exe` 替换为轻量桥接入口；原签名 EXE 逐字节保留为同目录 `Launcher.zml-original.exe`，参数经 Windows 标准引用后转发，工作目录保持原目录。原启动器负责登录、更新与普通启动。安装器记录 SHA-256，原始网页备份存入 `ZML\backups`。
- 本地服务只绑定 `127.0.0.1`，安装时选择端口和独立 256-bit 随机 capability。启动时优先复用登记端口；遇占用或 Windows 保留端口，自动绑定系统分配的可用端口，并在打开原启动器前同步面板地址和卸载校验记录。绑定持续持有，不通过结束其他进程或删除系统保留区间腾出端口；写入失败按字节回滚，外部修改拒绝覆盖。HTTP 限定 Host、Origin 和 token；无任意执行/路径访问接口。模组侧栏和主按钮适配无需 HGJsBridge、React 私有字段、Qt 私有 ABI 或外部网络，只读取当前主题与按钮/勾选的可见 DOM。服务随真实启动器退出而结束，重复开启不会创建多个服务。
- 勾选加载模组时先运行本仓加载器 `--dry-run` 校验，再一次性接入原启动器的客户端创建动作。不修改真实账号、服务器、凭据、存档或反作弊，
- 自有 ZML 子目录只给当前安装用户增加 Modify；不更改官方目录、游戏目录权限。建议从自己的日常 Windows 用户同意 UAC安装；换用户运行可能因权限不同无法保存模组开关。
- 安装先写持久恢复计划与原文件备份，失败恢复；下一次安装发现未完成计划时先校验恢复。开关通过原子替换与持久 journal 批量保存，校验失败回滚；重启服务后恢复未完成切换。外部更改/备份损坏拒绝覆盖。
- 官方更新可能覆盖网页或根入口。网页更新：退出后用同一个安装器“修复”，新网页作为恢复基线。根入口被替换或外部文件变化：明确报冲突，不盲目替换。需保留备份、处理冲突后重新安装；没有后台劫持更新器。
- GUI“安装 / 修复”在启动器关闭后升级自有网页与 bridge，保留框架、端口/token、Mod 和私人配置；旧安装不会追加另一包的 Mod。框架升级仍采用“卸载集成 → 新安装器安装”，保留 Mod。EXE 未签名，Windows 可能显示未知发布者/SmartScreen 提示；不要假称已取得签名或生产兼容认证。

## 构建

`tools/build-installer.ps1` 默认构建/测试 framework，再编译 GUI、桥接入口和安装测试，打包成单 EXE。使用系统自带 C# compiler，不增加第三方实现或 Mod 源码。

安装器 **只含加载器，不允许携带任何 Mod**；`build-installer.ps1` 不再接受 `-ModPackage`，解包和安装阶段也拒绝 `mods/` 条目。Mod 仍从独立仓库发行，用 `install-mod.ps1` 单独安装；CLI framework 的显式组合 zip 与 GUI 安装器不是同一种发行物。不提交或分发游戏网页、EXE、Qt DLL、账户数据库、研究样本、凭据或私人日志。

安装器支持管理员 CLI：`--install <launcher-dir> [Endfield.exe]` / `--uninstall <launcher-dir>`，供本地部署及自动化验证；不提供绕过权限的生产开关。

## 验证边界

安装/故障/回滚/卸载使用独立目录副本；启动路径使用自建 Win32 InjectionFixture，不用真实游戏存档。GUI/网页 fixture 与实际 Qt 启动器的显示、登录、更新、注入及普通启动需要分开记录，见 `docs/VALIDATION.md`。

有现成 Playwright 时运行实际浏览器链路：
```powershell
python tests/installer_web_tests.py --start build/installer/InstallerTests.exe build/installer/payload.zip build/tests/Release/InjectionFixture.exe
```
测试自行创建、停止自己的 bridge fixture，不操作真实启动器或游戏。不会通过关闭浏览器安全规则来伪造通过。

安装器还提供管理员 CLI `--refresh-ui <launcher-dir>`：仅更新已经注册的网页自有 JS/CSS，保持原网页、bridge、框架、模组和私人配置；有外部修改时拒绝覆盖。可在启动器打开时执行，当前文档不变，重新打开启动器后生效；该命令不会停止任何进程。

安装器支持管理员 CLI `--upgrade-launcher <launcher-dir>`：需要退出启动器（不要求退出游戏），校验登记文件后仅升级自己的根 bridge 和注册网页 JS/CSS。保留官方 EXE、网页、框架、端口/token、Mod 和配置；更新前备份当前自有文件与状态，普通错误按字节回滚。备份状态包含本地 capability，不要分发。`--refresh-ui` 仍不升级 bridge；0.1.2 的主按钮接入会检查服务能力，旧 bridge 会提示升级，不静默忽略 DX11。

适配限定当前原生 DOM 契约与中文/英文开始游戏标签。新版本、其他语言或未知结构会保持原启动行为而不误接入，需重新适配。主按钮的模组启动与原官方更新/账号启动流程是分开的，不能把 fixture 注入当成真实登录/更新/DX11画面验收。

## 原生启动链路实现

胶囊跟随原生宽度，仅增加一个 52px 模组按钮；保持 DX11 短标题及错误才提示。现在不再从 HTTP `/launch` 创建另一游戏进程，也不调用 `ShowWindowAsync` 或伪造 Qt 游戏启动消息。

勾选加载模组后：网页先请求 `/prepare-launch` 做 dry-run 与登记路径/自有 DLL 校验，再只重放一次原按钮的 click。原官方 handler 继续负责登录、更新、参数、DX11、创建游戏及开始/结束状态。自有 `ZMLNativeLaunch.dll` 通过普通 `LoadLibraryW` 加载到登记版本的 `Games.exe`，只将其主模块 IAT 的 `CreateProcessW` 接为一次性适配器，不覆盖已有其他 hook，不改官方磁盘文件或 Qt 私有 ABI。

适配器只处理本次登记的绝对游戏路径，核实新建进程真实路径后用普通 LoadLibrary 加载 `ZMLRuntime.dll`，成功才把原 CreateProcess 成功结果交还官方调用者。原生 `OnGameStart` 因真实启动自然触发，包括 Qt 渐隐、最小化/托盘行为与游戏状态跟踪；不是手动调用动画或最小化窗口。注入失败只回滚这次创建且路径确认的客户端，并返回原生创建失败；不停止已运行的游戏或其他进程。不读取/记录业务启动参数、账户字段或官方日志。

未勾选、未武装、其他程序及其他安装路径保持原创建行为。武装 60 秒过期，可以取消；原生未创建客户端时明确报告超时，不假报成功。当前支持原启动器非挂起的 CreateProcessW 路径；发现挂起/调试创建、导入契约改变或模块访问被拒绝就 fail closed，不绕过安全软件。不保证其他启动器版本与第三方 hook 兼容。

安装/修复在启动器关闭后更新自有 bridge、适配器和网页；可通过 `--upgrade-launcher` 增加并登记自有 DLL，保留 framework、Mod、token、私有设置；故障按原备份回滚。

## 启动器权限说明

本机原生 `1.6.0/Games.exe` PE manifest 是 `requireAdministrator`。桥接入口现在也请求管理员权限，用户正常通过 Windows UAC 确认后启动，不关闭/绕过 UAC。安装器仍要求管理员。确保桥接与原生启动器权限一致，避免权限不足导致模块读取失败。

路径发现、安装关闭检查及桥接存活检查改用 `PROCESS_QUERY_LIMITED_INFORMATION` + `QueryFullProcessImageNameW`；无需先读取目标模块来识别进程。真正接入仍需正常的Windows权限；模块访问被拒绝会报告Win32码与根入口重开说明，不伪装为未找到，不尝试权限/安全绕过。模组和配置保留。

## 游戏选项卸载入口与版本标识

安装器本身为独立框架，不内嵌模组内容。模组在独立的目录中进行管理与更新。

终末地「游戏选项」是原生 `CGameSettingDlg` / `CGameResource`。自有 `ZMLLauncherOptions.dll` 使用公开 Qt API，在窗口的卸载游戏按钮旁添加「卸载 ZML」按钮。通过线程消息钩子在 Qt GUI 线程操作控件，外观与原生按钮样式保持一致。

点击卸载按钮后运行 `ZMLUninstall.exe`，弹出二次确认对话框。确认后安全关闭相关进程，核验原文件备份并完整还原官方启动器入口与网页，移除加载器扩展组件。模组目录及用户个人配置文件将被完整保留在备份目录中。

在游戏加载 ZML 运行后，在开场登录版本面板（`Beyond.Login.LoginVersionPanel`）的原生版本文字后平滑追加 ` | ZML <版本号>` 标识，方便识别模组加载器运行状态。


## Qt 选项界面集成与样式复用

启动器选项中的 ZML 功能按钮通过运行时复用原生 Qt 样式与绘制逻辑实现：
- 通过识别原生按钮控件类型，直接借用原生样式的 `QStyleOptionButton` 与 `QStyle::drawControl` 进行绘制，保持与官方启动器外观完全一致。
- 安装 Qt 事件过滤器，在原生侧栏展示时自动适配并挂载相关操作入口。

## 安装器交互流程与安全机制

- **位置发现**：通过只读读取注册表中的官方启动器安装路径，并自动定位 `games/Endfield Game/Endfield.exe`，无需手动遍历磁盘。
- **进程安全检测**：在执行安装或卸载前，若检测到目标启动器进程仍在运行，将展示确认弹窗并在用户同意后安全退出对应进程，避免文件写入冲突。
- **备份与状态恢复**：每次修改前完整备份原文件并记录 SHA-256 哈希。若安装中断或失败，自动回滚至先前状态。
- **卸载恢复**：卸载时完整还原官方启动器文件与入口，原模组目录移动至备份归档，保留玩家个人数据。
